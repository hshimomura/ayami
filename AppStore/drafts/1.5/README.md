# あやみ 1.5 App Store紹介文案

日本語・英語、Mac・iPhone／iPad向けの1.5紹介文と編集方針。
原稿はこのディレクトリーの`metadata/`へ保持し、提出用の正本は`AppStore/metadata/`へ反映する。
日本語の名称とサブタイトルはユーザー指定を採用する。英語の名称とサブタイトルは維持する。

## 申請方針

1.4の申請を取り下げ、1.5（21）へ差し替えて提出する。
署名付きパッケージと処理済みビルドを確認してから、既存の申請を取り下げる。
Quick Lookの動画は制作せず、日英のスクリーンショットを用意する。
画像はAsset Libraryへ未提出の素材としてアップロードし、1.5の編集可能な掲載枠に追加する。
画像の保管とストア掲載・審査提出は別の操作であり、素材のアップロードだけでは公開されない。

## 紹介文の組み立て

冒頭は「READMEも、設計書も、読みやすく。」とし、エンジニアが読む場面を具体的にする。
AIが生成したMarkdownも対象に含めるが、アプリ自身のAI生成機能とは分けて説明する。

1.5の本文は次の順にする。

1. 検索と目次で、必要な記述へ移動できる。
2. ピンクの蛍光ペンで一時的にマークできる。閉じると消え、元文書やPDFへ保存しない。
3. Mermaidの拡大とコードのコピーで、図と実装を確認できる。
4. 相対画像・関連文書・HTML・ソースを、プロジェクトの資料として読める。
5. MacのLive ReloadとQuick Look、文字サイズ、印刷・PDFを説明する。
6. 対応環境と任意のAI試作機能を末尾に置く。

Macのタブ・ウィンドウ指定、Live Reload、Finder Quick LookをiPhone／iPadの説明へ混ぜない。
多段の取り消し履歴は未実装のため掲載しない。現在の個別解除と全消去だけを記載する。
HTMLのスクリプト非対応、ローカル画像、印刷・PDFの独立したレイアウトも説明する。

## 検証と掲載方針

Appleの[プロダクトページ作成ガイド](https://developer.apple.com/app-store/product-page/)に沿い、
利用場面を冒頭に、主な機能を短い項目にまとめる。検索順位の向上やダウンロード数の増加を保証する表現は使わない。
キーワードはREADME・設計書・Mermaidなどの関連語を選び、名称内のMarkdownの重複を減らした。
プロモーション文は利用者への訴求に使う。Appleはこの欄が検索順位に影響しないと説明している。

名称・サブタイトル30文字、プロモーション170文字、キーワード100文字、紹介文・更新内容4,000文字の範囲を確認した。

```sh
./Scripts/verify-app-store-metadata.sh
./Scripts/verify-app-store-metadata.sh AppStore/drafts/1.5/metadata
```

1.5の原稿を掲載する際は、配布するビルドの機能と一致させる。
1.4の公開履歴は既存のリリースノートで保持する。
既存の1.4更新内容は履歴として保持し、1.5の更新内容は新機能を中心に書き直した。
